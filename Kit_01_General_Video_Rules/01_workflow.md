# 01 — ترتيب الشغل (Workflow)

> الكلام مع اليوزر والكيك أوف (سؤال الكلاس `A/B/C/D`) مكانهم `..\TALK-TO-ME.md` و`..\START-HERE.md` قسم 3.

## A. شغلك جوه الخطة المعتمدة
- **Pick takes yourself.** When several AI shots or variants fit one script line, choose per VO sentence (timing, tone, what is said) and report which clip went where and why. Don't ask the user to pick. Unused clips stay as B-roll options.
- **Prompts go in the chat**, one code block per prompt (they may also be saved in the reel's plan). Never send them inside an old MD file — it confused the user about what was done.
- **Nothing gets built before the references and assets are in hand** (Omar, 2026-11-04: "ضروري تطلب مني الـ assets والريفرنس قبل ما تبدأ"). Two requests only:
  1. **Kick-off:** the reference(s) + everything that already exists (brief/script, logo, screenshots, client footage, approved VO). Say what each one is for. No analysis or Beats Plan without a reference — if there is none, propose 2–3 search terms / accounts and ask.
  2. **After the Beats Plan, before any build:** the full list of what must be made, all in one message with its prompts. Asking in batches made the user spend more time collecting assets than editing.
- **The Beats Plan ends with one line «الريل خلص لما: 1… 2… 3…»** `[ذوق عمر]`: max 3 conditions that can be checked on the MP4 (e.g. length, captions match the VO, logo outro), approved with the plan. Class C/D: the same line in the first plan message. Verify (§B.5) checks them before anything is called done (Omar, 2026-11-14).
- **Every asset request teaches how to get it** (§D table): which tool, the exact prompt in a code block, the settings (ratio, length, model), the steps if they're not obvious, and the file name + folder to save it in (`assets - <CODE> R<N>\` or `footage - <CODE> R<N>\`).
- Report the exact `inInfluence/outInfluence` used next to every beat when reporting a build.
- Flag every place where the brief disagrees with measurements (VO timing, frame numbers vs seconds, kashida position) — build on the measurement, say what changed.
- Other models' notes (e.g. Gemini): take the good ideas, and say plainly where their timing or colours are wrong.
- Every runner job saves the project and copies it to `_versions\` first (`04_ae_mcp_playbook.md` §2). A project that was never saved has no file → save it once (`app.project.save(File)`) in the reel folder before the first build.

## B. The 5-phase loop (per scene)
1. **Reference analysis** — cuts, camera momentum across cuts, entries/exits, overlaps, background drift. Analyse the **order** too, not only the elements: whatever moves first in the reference is our hook (in AG1 reel 2 the man at the start of the reference was the hook; it was missed, then placed at the wrong moment). Analysis only.
2. **Measure the VO** for the scene range (see `05_audio_sfx.md`) → real cut points. Always measure; timecodes from the user or from another model get checked by measurement (Gemini's drifted up to 2.3s).
3. **Beats Plan** — second-by-second (`0.0s, 0.2s, 0.6s…`) in scene-local frames. Before presenting check: anything at a dead stop? anything linear/isolated without overlap? → fix. **STOP and wait for approval** (class A/B; the user may authorize "build directly").
4. **Idempotent build** — one script that deletes its previous comp by name and rebuilds; logs to a `_result.txt` next to the script.
5. **Verify** — contact sheet + Render-Queue frames + **the MP4 itself with VO** (see `04_ae_mcp_playbook.md` §Verify). Never say "done" before checking.
6. **Learn** — every user correction becomes a numbered rule (exact numbers + why) in its one place (table in `..\START-HERE.md` §7) + a line in `..\CHANGELOG.md`.

## C. Session & state hygiene (توفير التوكينز)
- **One scene per session** for long projects; keep a `PROJECT_STATE.md` handoff in the reel folder root: locked decisions table, VO markers, per-scene summary (structure, frames, colors, audit numbers, preview path, approval status), and a "Next step". Update it after every scene / decision before ending the turn.
- New session order: `..\START-HERE.md` → this kit → client file (`Kit_04_Clients`) → brand/style kit if needed → `PROJECT_STATE.md` → continue from "Next step".
- مراجعة أي فيديو أو صوت تروح لـ `agy` (Antigravity، `gemini-4-neon-high` من 19 نوفمبر 2026 على اشتراك Google AI Pro بتاع عمر) بسكيل `free-llm-delegate`. هو العين اللي بتشوف والودن اللي بتسمع، والناتج يتحفظ في ملف وأقرا منه اللي محتاجه بس. متتفرجش على فريمات كتير بنفسك لو `agy` يقدر يوصفها. التفكير والكتابة والتلخيص وأي شغل تاني ميروحش لأي موديل تاني (لا `agy` ولا المجانية ولا مفتاح `Gemini`) غير لما عمر يطلب (قرار عمر يوم 6 نوفمبر 2026).
- ملف `PROJECT_STATE.md` يفضل قصير (أقل من 150 سطر): القرارات والحالة والخطوة الجاية. التاريخ القديم يتنقل لـ `PROJECT_HISTORY.md`.
- **لما عمر ينقل ريل لاكونت تاني** (زي اكونت الشركة)، اكتب `HANDOFF.md` في فولدر الريل وحط في أول `PROJECT_STATE.md` سطر بيشاور عليه. الملف فيه:
  - جدول الماتيريال: كل ملف بمساره وفيه إيه، واللي اتشال واتشال ليه.
  - تفريغ الكلام بالتوقيتات، والسكوت المقاس.
  - شكل آخر نسخة بالثواني، و**النسخة المعتمدة باسمها وبصمتها (`md5`)**، مش آخر `export`. لو بعدها اتعملت نسخة اترفضت، اكتب إن السكريبتات بتبني النسخة المرفوضة، وإيه اللي يرجع. في CLA R1 الملف قال إن المعتمدة v9، وطلع إن عمر معتمد v7 (`YUGEN_R1.mp4` نفس بصمتها)، وv8 وv9 كانت ساوند جديد مرفوض وزووم أوت.
  - الأوامر بالترتيب عشان يعدّل ويبني.
  - ملاحظات عمر نسخة بنسخة، والحاجات المفتوحة.
  - ماتنساش برومبت جاهز يلزقه في الجلسة الجديدة، وإيه اللي يتنقل لو الجهاز مختلف.
  - الهدف إن الاكونت الجديد ميعيدش أي تحليل (CLA R1، 10 نوفمبر 2026).
- Build one precomp at a time; don't build the whole video in one go unless asked.
- **Every scene comp gets a `CTRL` null** (`tools/ctrl_rig.jsx`, pulled in with `// claude-include:`): sliders/points for the values the user nudges by hand (each title's delay in frames, offset, size %). The build reads the old CTRL values with `ctrlRead()` before deleting the comp and puts them back, so a rebuild keeps the user's tweaks. Tell the user to tweak from CTRL, not keyframes.
- **Edits outside CTRL are still lost on rebuild** (keyframes moved by hand, new layers). If the user changed anything outside CTRL, read their values first (MCP / read-only job) and only rebuild if asked; after final approval, changes go through small targeted scripts only. `_versions\` has the state before every build if something gets wiped.
- **The brief names the takes → analyze only those.** Other clips from the same shoot are not backups to check "just in case" (CLB R2: brief named C0418/C0421/C0419; I also reviewed C0417/C0420 and Omar asked why).
- Don't scan media folders (`Assets/`, `Previews/`, `footage - …`, stems) and never Read a video/audio file. To choose between many clips: one `ffprobe` pass (duration, size, fps, audio) + one 8-frame strip per clip (`fps=8/<dur>,scale=180:-2,tile=8x1`), stacked 5–7 clips per image → 17 clips judged from 3 images (CLD R1). Many clips: 3 frames per clip (10/50/90% of duration, 200px) (keep the aspect: `scale=200:-2`, never a fixed 16:9 resize) with 5 clips per row in one PIL image → 35 clips in one image, and start→end shows the camera move (push-in/pan) (CLB R1). Reference cut timing: `scdet` (threshold 8) is the measurement, but it misses rapid-zoom openers of 2–4-frame blurred shots (scores 3–7) → check the first 2 s with an every-2-frames strip (`select='not(mod(n\,2))',tile=10x3`). Pick fast; the user said don't spend tokens choosing footage.
- **Before analysing any shoot, look for its index** `[تقني]`: `<shoot>\_index\footage_index.json` (a shoot inside Dropbox: the reel's `work\footage_index\`, so nothing new syncs to the client). None → run `tools\footage_index.py <shoot> [--out …]` once (the ffprobe pass + the 35-clip sheets above, plus luma/burnt %, camera move at 10/50/90 %, warning flags) and pick from it; what the eye sees goes in each clip's `notes`, which a re-run keeps (plan 8-c, CLB 4-11 shoot, 2026-11-14).
- **The folder the session is open in is locked by Windows**: it can't be moved, renamed or removed (CLD R1). Move its contents (`robocopy /E /MOVE`), switch the session to the new folder, and leave the empty one for the user.
- Keep a `.claudeignore` in the project: `Assets/ *.mp3 *.png *.jpg *.jpeg *.mp4 *.wav *.tif`.
